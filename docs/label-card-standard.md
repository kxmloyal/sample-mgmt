# 标签与标示卡标准化规则（v1.0）

> 本规范定义制造品质管理系统**样品子系统**中「标签」与「标示卡」的标准化规则：两者的定义、格式规范、使用场景、相互关联关系及**双向更新（数据一致性）机制**。
> 适用范围：所有涉及标签/标示卡的新增、修改、重构代码与文档。AI agent（含 Claude、Codex、Gemini 等）在改动相关代码前 MUST 阅读本规范并遵守。
> 依据：`subsystems/samples/backend/card-html.js`、`card-print-html.js`、`card-page.js`、`routes-cards.js`、`card-constants.js`、`routes-scan.js`。

---

## 一、定义

| 对象 | 英文 | 定义 | 承载形态 |
|---|---|---|---|
| **标签** | Label | 贴于样品实物的**标签纸打印视图**，2:3 布局：左侧 QR 码 + 基本信息，右侧**空白标示卡区**（虚线框占位） | 打印页（自动打印）/ 下载页（HTML 附件） |
| **标示卡** | Card | 承载样品关键品质信息的**内容卡**，贴入标签右侧空白区，三种形态 | ①打印版（无 QR）②数字标示卡（匿名扫码）③编辑表单（详情页 8 字段） |
| **二维码** | QR | 编码于标签左侧，内容为 `qr_token \|\| sample_no`（不可枚举 token，存量空值回落编号） | PNG（预览 320px / 下载 600px / 打印按尺寸缩放） |

### 1.1 术语约定

- **空白标示卡区**：标签纸右侧的虚线空栏，打印后供人工粘贴标示卡实物。
- **数字标示卡**：`GET /card/:sample_no` 匿名页面，供现场扫码查看。
- **打印版标示卡**：`GET /api/samples/:id/card/print`，无 QR，纸张=标签空白卡区尺寸。

## 二、格式规范

### 2.1 标签纸尺寸（唯一数据源：`card-constants.js` 的 `PRESET_MM`）

| 档位 | 预设 (mm) | 说明 |
|---|---|---|
| 小号 `small` | 37 × 18 | 标签页与标示卡页共用，**禁止各自硬编码** |
| 中标 `medium` | 52 × 25 | |
| 大号 `large` | 60 × 40 | 默认档 |
| 自定义 `custom` | 宽 30~150 / 高 10~150 | 宽或高非法/缺失时回退大号 |

> 换算：**1mm ≈ 3.7795px @96dpi**。`@page` 纸张尺寸与 `.lab`/`.sheet` 尺寸 MUST **同源取 mm**，避免 px/mm 舍入差导致打印分页溢出。

#### 2.1.1 自定义尺寸的比例兼容（contain 缩放）

自定义尺寸（宽 30~150mm / 高 10~150mm）支持**任意宽高比**（如 60×40、80×40、40×140、60×60 等），处理规则：

1. **标签布局 = 真实纸张物理尺寸**：`.lab` 宽高直接用输入的 `cw/ch`（mm），标签页**永远铺满纸张**，不因比例改变而裁切或留边。
2. **内容 contain 缩放**：以内容基准 `280×133px ≈ 74.2×35.2mm` 为参照，`scale = min(cw/74.2, ch/35.2)`——取宽、高两方向较小者，保证内容（QR+基本信息+空白卡区）**完整放入、不溢出不裁剪**；QR 下限 12px、字号下限约 5px。
3. **空白卡区弹性**：右侧空白卡区以 `flex:1` 吃掉剩余宽度，随比例自动伸缩。

**边界行为**（比例严重偏离内容基准约 2.1:1 时）：

| 比例场景 | 表现 |
|---|---|
| 横向极宽（如 100×35） | `scale` 由高度决定，横向留白多，空白卡区变宽 |
| 纵向极高 / 近方（如 40×140、60×60） | `scale` 由宽度决定，内容偏小、上下留白明显，空白卡区可能偏窄 |
| 极端窄条 | 卡区过窄时文字换行/挤压（QR/文本有最小值保护，但视觉紧凑） |

> 结论：此模型保证**完整、不裁切**，代价是比例差异大时内容偏小、留白增多（标准 contain 语义）。若需内容**铺满整纸**（fill 语义，放大到贴边裁切），需另按方向拉伸，当前非如此设计。

### 2.2 标签字段（QR 侧）

编号 `sample_no` / 名称 `name` / 机型·站别 `model·station` / 规格 `spec`。字号与二维码随标签尺寸自动缩放（字号下限约 4pt；二维码按纸高剩余空间自适应，余量不足时收紧文本为单行优先保障可识别）。

### 2.3 标示卡字段（打印版 8 字段 + 备注）

类型 `sample_type` / 来源 `source_type`（代码+简称，如 `G·塔岗`） / 版次 `card_version` / 项目 `limit_item` / 有效期 `valid_until`（`yy/mm/dd`，过期标红） / 样品数值 `test_data` / 制作 `signed_by_rd` / 确认 `signed_by_qa` / 备注 `notes`。

> 数字标示卡（`card-page.js`）在打印版基础上额外展示：样品名称、机型/站别/规格、最近 2 条操作日志。

### 2.4 尺寸联动

**标示卡纸张 = 标签纸去掉 QR 侧边的空白卡区尺寸**（`blankWmm × blankHmm`），计算式与 `card-html.js` 的 `.lab` 布局公式保持一致。

标示卡内容按 155×92px 基准渲染，`fitCard()` 测量后整卡 **contain 缩放**（`scale = min(sheetW/cardW, sheetH/cardH)`），保证完整无裁切。

### 2.5 版次机制

| 场景 | 规则 |
|---|---|
| 新建样品 | 默认 `01`（可传入覆盖） |
| 首次发行 | 默认 `01` |
| 复检 / 再发行 | `nextCardVersion()` = 当前最大数字 +1，上限 99，`padStart(2,'0')` |
| 替代品 | 复制原标示卡信息（card_version / test_standard / test_data 等） |

## 三、使用场景

| 场景 | 触发方 | 接口 | 权限 |
|---|---|---|---|
| 新建样品 | 自动弹出标签打印 | `GET /api/samples/:id/label/print` | 登录 |
| 下载标签 | 列表/详情「下载标签」 | `GET /api/samples/:id/label/download` | ADMIN/QA/RD |
| 打印标示卡 | 发行后自动 / 详情页手动 / 打印队列批量 | `GET /api/samples/:id/card/print` | 登录 |
| 下载二维码 | 条码打印软件导入 | `GET /api/samples/:id/qrcode/download` | ADMIN/QA/RD |
| 扫码查看数字标示卡 | 现场扫码（匿名，无需登录） | `GET /card/:sample_no` | 公开 |

## 四、相互关联关系

1. **同源派生**：标签与标示卡均从 `samples` 表**实时派生**渲染，无独立存储。
2. **尺寸联动**：标示卡纸张 = 标签空白卡区，两页共用 `PRESET_MM` 与换算系数。
3. **QR 关联**：扫码打开数字标示卡；`qr_token` 不可枚举，防止遍历。
4. **版次联动**：版次随发行/复检递增，标签与标示卡同步反映。
5. **唯一缓存**：仅 QR 有 LRU 缓存（上限 200，键 = `sample_no/qr_token + width`），缓存内容仅依赖二维码编码内容，与品质字段无关。

## 五、双向更新机制（数据一致性规则）

**原则：唯一事实来源 = `samples` 表**。标签与标示卡均**不存独立副本**，任一信息变更只需更新 `samples` 表一次，另一视图下次打印/查看即自动反映最新值。

| 变更场景 | 处理 |
|---|---|
| 字段变更（数值/来源/有效期/版次/签署等） | 更新 `samples` 表 → 标签/标示卡**自动同步** |
| 已打印旧纸 | 字段变更后旧纸内容不更新，**需人工重新打印并更换实物上的旧纸** |
| 禁止行为 | **禁止**为标签/标示卡建立独立数据副本、持久化缓存、冗余快照字段 |

---

## 六、边界与禁止事项

1. 禁止在 `app.css` 中写标签/标示卡专属样式（写入 `subsystems/samples/frontend/css/module.css`）。
2. 禁止跨子系统引用卡片文件；标签/标示卡仅属样品子系统。
3. 尺寸常量 MUST 从 `card-constants.js` 引用，禁止各文件硬编码。
4. 数字标示卡为**公开匿名**接口，仅暴露样品质检信息，不得泄露用户/部门敏感数据。
