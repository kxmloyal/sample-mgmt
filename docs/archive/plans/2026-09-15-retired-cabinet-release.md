# 作废样品柜位释放（`gone` 分桶 + 清柜动作）— 实现计划

> 迭代日期：2026-09-15（编码）/ 2026-09-16（发布、部署、数据订正）
> 发起：用户提问「目前作废的样品还保留在样品柜中，这样的设计原因是什么？是否合理？」

## 1. 触发证据（2026-09-15 线上只读实测）

| 证据 | 数值 |
|---|---|
| 状态分布 | `IN_CUSTODY` 91（**全部有储位**）/ `CHECKED_OUT` 7 / `RETIRED` 26（**26/26 有储位**，作废原因全部为「退回研发重新制作」）|
| `reserved` 池构成 | **26/26 全部是作废残留**（真实预占 0 件）→ 该桶实际语义与命名背离 |
| 受影响格位 | 452 格位中 **8 格**：`1#样品柜 3-7`(0 在柜/3 作废)、`1#样品柜3-8`(0/2/2)、`1#样品柜3-9`(6/6)、`2#样品柜5-1`(6/4)、`2#样品柜5-2`(5/1)、`4#样品柜3-11`(2/2)、`4#样品柜3-4`(10/6)、`4#样品柜3-8`(2/2) |
| 显示缺陷① | **7/8 格件数角标虚高**（作废件混入角标）：最高 `4#样品柜3-4` 角标 16，实际在柜仅 10（**+60%**）|
| 显示缺陷② | `1#样品柜 3-7` 是唯一「纯被占」格：0 在柜、3 作废，却因 `total=0` 渲染成 **`sm-empty`**（看着能放样）|
| 显示缺陷③ | 顶栏图例仅 4 态，**无作废残留说明**；格位清单状态直接回显英文 `RETIRED` |
| 报表口径 | 「在用」124 件中含 26 件作废残留（**21.0%**）|
| 控制层缺口 | 应用内**无任何释放格位路径**：`EDIT_STORAGE` 要求储位非空、`PUT /api/samples/:id` 对 RETIRED 直接 409 且仅接受标示卡字段、`DELETE` 仅限 NEW/PRODUCED |
| 可追溯性依据 | 26 件 `CUSTODY` 日志 **26/26 带 location**；`EDIT_STORAGE` 日志 **0 条** → 释放储位不会丢失既有痕迹 |

**结论**：数据层「作废后保留储位」**合理**（作废 ≠ 立即离柜，保留最后已知位置便于处置追溯）；**显示层与控制层有缺陷**——既说不清该格为何占着，也没有释放手段。

## 5. 验收标准

- 分桶：`gone`/`reserved` 分离；`occupied` 含 `gone`；`summary.gone` 纯增量（旧前端无感）
- 清柜：仅 `RETIRED` 可达；非 RETIRED → 409、无储位 → 400；原储位入 `scan_logs.location`；不可撤销
- 显示：图例 5 态；角标只计真实占位并单列「废N」；**纯作废格位不得复用 `sm-empty`**；状态中文化无英文回显
- 兼容：旧前端不读 `gone` 行为不变；新前端遇旧后端 `occ.gone || 0` 行为同改造前
- 隔离：仅 samples 改动；其它 4 个子系统 `index.html` / `bundle.js` 零 diff
- 回归：静态断言全绿（唯一失败为本地无 `node_modules` 的环境性用例）

## 6. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 清柜被误用于在柜样品 | manifest 转移门 + 后端二次状态校验（409）+ 前端按钮仅对 RETIRED 渲染 |
| 清柜后位置不可追溯 | 原储位写入日志 `location`（详情时间线可见）|
| 拆桶引发空位误判 | `occupied` 含 `gone`：清柜前该格仍算占用，绝不放行 |
| 旧后端无 `gone` 字段 | `occ.gone \|\| 0` 兜底 → 行为与改造前完全一致 |
| 前端先上线、后端未重启 | 新前端 + 旧后端完全兼容：仅功能不出现，无报错 |
| 两处格位渲染漂移 | 图例共享 `smLegendHtml`；格位渲染仍分两处 → 已登记「合并 `smCellHtml`」待办 |

## 9. 口径修正（2026-09-16，v2.0.8）

用户明确业务规则：**清柜释放储位应发生在作废时、柜位同步清理**，不设「作废后再单独清柜」的人工后置步骤。据此 §1–§8 的方案被修正：

| 项 | 原方案（v2.0.7） | 修正后（v2.0.8） |
|---|---|---|
| 释放时机 | 作废后由保管/生技/ADMIN 扫码执行「清柜释放储位」 | **作废/退回研发重做时自动同步释放**（`releaseCabinet`） |
| 覆盖出口 | 仅 `CLEAR_STORAGE`（RETIRED→RETIRED 自环） | `RETIRE_ONLY` / `FORCE_RETIRE` / `RETIRE_RECREATE` / `RECREATE`（4 个） |
| 独立清柜动作 | manifest 新增第 18 条转移 | **已删除**（回退 17 条）；前端第 5 态与「废N」角标一并回退 |
| 「作废残留」分桶 `gone` | `occupied` 含 `gone` | **随动作一并回退**（恢复四段口径）；存量 0 件且该字段从未激活，无需兼容分支 |
| 留痕 | 额外一条 `CLEAR_STORAGE` 日志 | **并入作废日志**：note 追加「，同步释放柜位 X」+ `location` 列写原储位 |
| 历史兼容 | — | 2026-09-16 订正的 26 条 `CLEAR_STORAGE` 日志**保留渲染映射**（§6.3 禁直接删除枚举常量） |

**已知行为（用户决策的必然代价，已写入帮助指南与发布说明）**：
- `RETIRE_RECREATE` 后状态仍为 `RETURNING` 且已无储位 → 在研发创建替代品前，该样品会出现在柜位视图顶部「未入柜样品」告警区（该池收在柜三态）。
- 该窗口内若被「拒绝退回」驳回，样品回到保管中但**无储位**，需保管用「修改储位」重新登记（可恢复，无数据丢失）。

**实施记录（2026-09-16，v2.0.8）**：新增 `releaseCabinet` 助手 + 4 个作废出口接线（`scan-actions.js`，顶层函数 7→8）；manifest 18→17；前端纯回退 5 文件（`storage-map.js`/`storage-loc-picker.js`/`module.css`/`report.js`/`detail.js`）+ 4 处「柜位将同步释放」确认提示（`scan-return-actions.js` 助手）+ 作废类动作纳入格位缓存失效（`scan.js`）；测试回退 2 条旧断言并新增 1 组「作废即清柜」契约（含 bundle 落地自证）；bundle 重建 `bmu2kg6y6` → `bmu3he1a0`。详见 `docs/RELEASE-v2.0.8.md`。
