# 角色权限对照表（Role-Permission Matrix）

> 数据来源：各子系统 `manifest.json` 的 `stateMachine.transitions` 与 `navigation.roles`（单一事实来源，AGENTS.md §17.3）。
> 更新方式：修改 manifest 后同步本表；本表仅供查阅，不参与运行时校验。
> 最近同步日期：2026-09-04（SUBMIT+QA、会签按部门、治具验证收紧、管制子系统全量、**多角色架构上线**）

## 〇、多角色架构（2026-09-04 上线）

- 一人可**并存多角色**：`user_roles` 关联表（主角色 = 角色列表第一个），管理员在「用户管理」界面配置
- 判定语义：**职能门槛**（绝大多数流转/导航/待办）= 任一角色命中即通过；**部门门槛**（下表标注 🔒 的动作）= CUSTODY 须部门命中
- 待办投递：按全部角色的并集聚合（行动主体口径不变）
- 部门门槛策略单一来源：`data/control-flow.json` 的 `flowPolicy`（管制仓口 4 动作）与部门别名 `deptAliases`
- 归还/验证等当事人动作按借用关系/申请部门判定（治具 RETURN：借用人本人/同部门/ME/ADMIN）

| 退回审核中 → 已作废 | 直接作废 | QA |
| 退回审核中 → 保管中 | 拒绝退回 | QA |
| 已发行 ⇄ 已发行 | 复检 | QA |
| 已发行 ⇄ 已发行 | 修正标示卡 | QA |
| 保管中 ⇄ 保管中 | 修改储位 | CUSTODY / ME |
| 退回审核中 ⇄ 退回审核中 | 退回研发重做 | QA |
| 退回审核中 → 已作废 | 创建替代品 | RD |

## 三、治具管理（fixtures）

**导航权限**：看板 / 清单 / 新建申请 / 扫码台 / 操作日志 = 全部角色

| 状态转移 | 操作 | 允许角色 |
|---|---|---|
| 已申请 → 已接收 | RD接收 | RD |
| 已申请 → 已废弃 | 撤销申请 | RD / ADMIN |
| 已接收 → 待验证 | 制作完成 | RD |
| 待验证 → 已移交 | 验证移交 | **申请部门人员**（谁申请谁验证）+ ADMIN 兜底（2026-09-04 收紧） |
| 已移交 → 领用中 | 领用 | ME / QA / CUSTODY |
| 领用中 → 已移交 | 归还 | 领用人（ME / QA / CUSTODY 均可代办） |
| 领用中 → ME维修中 | ME自行维修 | ME |
| 领用中 → RD维修中 | 退回RD维修 | ME |
| ME维修中 → 维修完成 | ME维修完成 | ME |
| RD维修中 → 维修完成 | RD维修完成 | RD |
| 维修完成 → 已移交 | ME确认维修 | ME |
| 领用中 → 改善中 | 申请改善 | ME |
| 改善中 → 已废弃 | 改善完成 | ADMIN |
| 已移交 → 已废弃 | **报废** | **仅 ADMIN** |
| VERIFY_RD_OK/VERIFY_ORG_OK（历史死锁态） | 强制移交 | **仅 ADMIN** |

> 注意：MAKE（制作完成）前置要求「设计图纸 + 实物照片」两类文件齐全，RD 缺文件会被 409 拦截（routes 层校验）。
>
> **我的待办口径（2026-09-04，行动主体才看待办）**：待验证/可领用/改善中→申请部门(+RD/ME)；归还逾期→借用人本人+借用部门+ME；保养到期→ME；死锁态→ADMIN。待办≠部门广播，allowedActions 权限本身不变。

## 五、管制流程（control）

**导航权限**：全部菜单 = ADMIN / RD / QA / CUSTODY / ME（操作日志仅 ADMIN）；新建管制申请 = 登录即可（各部门起草本部门申请）

| 状态转移 | 操作 | 允许角色 | 部门门槛 |
|---|---|---|---|
| 申请草稿 → 管制会签中 | 提交会签 | QA / CUSTODY / ME | 仅**申请部门**（2026-09-04 起 QA 加入）；重提时**清空闸口①旧签字**，全部字位重新会签（2026-09-04 会签退回闭环） |
| 管制会签中 → 已贴管制标签 | 闸口①通过/贴标 | QA | 闸口① 5 字位（品保/研发/生管/制造部/仓库）全部同意后 |
| 管制会签中 → 申请草稿 | 闸口①会签退回 | 轮到的签字人 | **会签动作**（「去会签」弹窗选退回，意见必填、签字人留痕）；~~流转按钮已下线~~（2026-09-04 方案A） |
| 已贴管制标签 → 已入管制仓 | 入管制仓 | CUSTODY | 仓库口（资材部） |
| 已入管制仓 → 委托单已开 | 开不良品委托单 | QA | — |
| 委托单已开 → 处理会签中 | 发起处理方式会签 | QA | 重工SOP 必填 + 指导/其他至少一项；重建闸口②模板前先清历史残留（幂等） |
| 处理会签中 → 重工工单已开 | 闸口②通过 | QA / RD | 闸口② 2 字位（品保/研发）全同意；填处理方式结论 |
| 处理会签中 → 委托单已开 | 闸口②会签退回 | 轮到的签字人 | 同闸口①：会签弹窗退回，意见必填；重新发起处理方式会签后全部字位重签 |
| 重工工单已开 → 重工执行中 | 生产确认开工 | ME | 填重工工单号 |
| 重工执行中 → 已报工 | 报工（确认） | CUSTODY / ME | 前置：已有报工记录且结余=0（2026-09-04 加固） |
| 已报工 → 已入库 | 入库 | CUSTODY / ME | 仓库口（资材部/生管部） |
| 已入库 → 已出货 | 出货 | CUSTODY / ME | 结余必须=0（数量=良+不良+报废） |
| 任意中间态 → 已作废 | 作废 | **仅 ADMIN** | — |

**会签部门制（2026-09-04）**：并行会签，任一未签步轮到即可签，但**按部门区分**——角色+部门双匹配，同角色不同部门（生管/制造部/仓库）不可互相代签；ADMIN 兜底代签/强制跳过。报工记录追加（REWORKING 状态）：生产口 CUSTODY（制造/生管/资材部）/ ME，可多次分批。

**会签退回闭环（2026-09-04 方案A）**：退回 = 会签弹窗的 REJECT 决定（意见必填、签字人留痕到 control_signs），流转接口已封禁 SIGN_REJECT/DISPOSAL_REJECT 旁路；重提（SUBMIT/重新 DISPATCH）事务内**清空对应闸口全部旧签字行并重建空模板**——杜绝"旧 AGREE 带病生效"与"重签被 400 锁死"。

**仓口部门门槛（🔒 2026-09-04 下沉授权层，后端 403 硬校验）**：STORE 入管制仓→资材部；REPORT 报工→生管/资材/制造部；IN_STOCK 入库 / SHIP 出货→资材/生管部。门槛仅约束**纯 CUSTODY 角色**用户（兼任 ME/QA/ADMIN 不受限）；策略源 `control-flow.json flowPolicy`，待办投递/前端按钮/后端 403 三处同源。
