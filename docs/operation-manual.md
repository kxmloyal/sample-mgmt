# 制造品质管理系统 — 操作说明书

> 适用版本：v2.x | 最后更新：2026-09-04（新增管制子系统全流程章节、工作台「我的待办」；同步治具验证/领用口径与会签部门制）

## 一、系统概述

制造品质管理系统含**样品管理**、**治具管理**、**管制流程**、**项目追踪**与**全局工作台**等子系统，通过统一门户入口（portal.html）进入，三方扫码驱动状态流转，全程留痕。

### 1.1 样品管理子系统

覆盖样品从「建样→制作确认→发行→保管→复检」全生命周期。

| 角色 | 代码 | 职责 | 典型账号 |
|---|---|---|---|---|
| 研发 | RD | 建样、打印贴样、扫码确认制作完成 | rd01 |
| 生技 | ME | 同保管：扫码接收、登记储位、申请退回 | me01 |
| 品保 | QA | 扫码确认发行、设置复检周期、复检 | qa01 |
| 保管 | CUSTODY | 扫码接收、登记储位、日常保管 | mfg01 / fqc01 |
| 管理员 | ADMIN | 用户管理、全局查看 | admin |

> 生技部(ME)属于保管单位，不可建样和确认制作。

**状态机**：`新建·待制作确认 → 制作完成 → 已发行 → 保管中 → 退回审核中 → 已作废`

### 1.2 治具管理子系统

覆盖治具从「申请→制作→验证移交→领用→维修/改善→报废」全生命周期。

| 角色 | 治具职责 |
|---|---|
| 研发(RD) | 制作治具、维修治具（RD维修中）|
| 生技(ME) | 保养治具、ME侧验证/确认维修、领用 |
| 品保(QA) | 验证移交、领用（同 CUSTODY）|
| 各部门保管(CUSTODY) | 验证移交、领用 |
| 管理员(ADMIN) | 报废治具、全局查看 |

**状态机**：`已申请→已接收→待验证→已移交→领用中→(维修/改善)→已报废`

> 验证为**单人验证**：制作完成后，由**申请部门人员**扫码验证即可移交，无需研发二次确认。

### 1.4 管制流程子系统

覆盖不良品从「申请→会签→贴标入仓→开 NCR 委托检验→处理方式会签→重工→入库出货」全流程闭环，电子表单对应纸质 GYS-Q2-008_01《不良品委托检验单》。

| 角色 | 管制职责 |
|---|---|
| 各部门（登录即可） | 新建管制申请（本部门起草）、闸口会签（按部门字位） |
| 品保(QA) | 闸口①通过/贴标、开不良品委托单、发起处理方式会签 |
| 保管(CUSTODY) | 入管制仓、报工、入库、出货（按仓口部门参与） |
| 生技(ME) | 生产确认开工、报工、入库、出货 |
| 管理员(ADMIN) | 作废、会签兜底代签、强制跳过会签 |

**状态机**：`申请草稿→管制会签中→已贴管制标签→已入管制仓→不良品委托单已开→处理方式会签中→重工工单已开→重工执行中→已报工→已入库→已出货`（任意中间态可由 ADMIN 作废）

> 会签为**并行会签 + 按部门区分**：闸口①5 个字位（品保→研发→生管→制造部→仓库）可同时签，但每人只能签自己部门的字位，不能互相代签。

### 1.5 全局工作台子系统

跨部门汇总样品 + 治具 + 管制 + 项目的活跃工作，按部门展示积压情况，帮助各部门掌握整体进度；**「我的待办」**聚合五个子系统所有轮到「我」处理的事项。

| 功能 | 说明 |
|---|---|
| 统计卡片 | 总计 + 各部门卡片，互斥三档积压（≤3 天 / 3~7 天 / 7 天以上） |
| 卡片交互 | 单击部门卡筛选该部门数据、再次单击取消；单击总计卡清除筛选 |
| 筛选栏 | 类型 / 积压等级 / 负责部门 / 申请部门 / 编号名称搜索 / 仅呆滞 / 停留时长范围多维筛选，服务端过滤，「共 N 条」实时计数，一键清除 |
| 分页与记忆 | 列表分页（上一页/下一页 + 页码）；筛选条件与页码写入网址（hash），刷新页面后自动恢复 |
| 我的待办 | 跨子系统聚合个人待办（见 §17），单击直达详情 |
| 阈值设置 | **仅管理员(ADMIN)**：工作台右上「阈值设置」可调整 3 天 / 7 天边界，保存后全局生效 |

> 普通用户无需配置，按管理员设定的阈值查看即可；标签文字会随阈值自动变化（如「≤5 天 / 5~10 天 / >10 天」）。

## 二、登录

1. 打开系统页面，输入**账号**和**密码**
2. 点击「登录」或按回车
3. 登录后左侧显示菜单，右侧显示**首页概览**

> 演示账号：admin/admin123 · rd01/rd123 · qa01/qa123 · mfg01/mfg123 · fqc01/fqc123 · me01/me123

### 2.1 修改密码（自助）

1. 登录后在门户页右上角（账号旁）点击「**修改密码**」
2. 依次输入**原密码**、**新密码**（至少 6 位）、**确认新密码**
3. 点击「确认修改」，成功后需**重新登录**（原会话已失效）

> 新密码至少 6 位，不能与原密码相同；忘记密码请联系管理员重置。

## 三、首页概览

登录后默认进入概览页，显示：

- **统计卡片**：总样品数、待制作确认、已发行待接收、保管中、复检逾期
- **我的待办**（按角色自动筛选）：列出需要你处理的样品，点击「去处理」跳转扫码台
- **复检逾期预警**（如有）：列出应复检但超期的样品

### 3.1 门户卡片个性化排列

门户首页的子系统卡片支持按个人习惯调整顺序，偏好仅对当前登录账号生效：

1. 在门户欢迎语旁点击「**编辑排列**」进入编辑模式，每张卡片右上角出现 ⋮⋮ 拖拽手柄
2. **按住卡片拖拽**到目标位置后松开，即可实时预览新顺序（此时尚未保存，仅修改当前浏览效果）
3. 点击「**保存顺序**」统一提交，出现「已保存排列顺序」提示；下次登录仍保持该顺序
4. 若不想保存本次调整，点击「**取消**」丢弃，顺序回退到上次保存的排列
5. **恢复默认**：再次进入编辑并保存（或由系统清除偏好）即恢复子系统默认顺序；未调整过顺序的新账号始终按默认顺序显示

> 说明：新增子系统、新建账号无需任何配置，自动按默认顺序排入门户。

## 四、建样（研发）

### 4.1 新建样品

1. 点击左侧菜单「新建样品+打印码」
2. 填写**基础信息**（左栏）：
   - **样品名称** *（必填）* — 如「1225震动样」
   - **规格/型号** *（必填）* — 下拉选择机型（需先在机型列表添加，选择后自动填入机型编码）
   - **机型编码** — 选择规格/型号后自动填入（至少 6 位）
   - **提供处** *（必填）* — 客供(C) / 元山(T) / 塔岗(G)
   - **组别** *（必填）* — 下拉选择（扇叶组/马达组/成品组/品保部/SMT/供应商）
   - **备注** — 自由文本
3. 限度样品信息（右栏，选填）：
   - **样品类型**：OK样品 / NG样品
   - **限度项目**：下拉选择（如「成品震动」「外观」等 26 项）
   - **版次**：首发自动 `01`，复检/再发行自动 +1（如 `02`→`03`，最高99），也可手动输入（如 `03`）
   - **标准范围**：如「震动≤0.5mm」「噪音≤30dB」— 这是限度判定标准，不同于标示卡上的「测试数据」（实测数值）
   - > 注：标示卡上的「测试数据/样品数值」在品保发行或复检时填写；「制作签署人」由系统自动填入当前登录用户
4. 点击「创建样品并生成条码」
5. 系统自动生成**13 位结构化编号**（如 `G-YD9015-Q-001-01`：提供处1位-机型6位-组别1位-流水号3位-版次2位），编号生成后固定，不随版次变化。弹出**标签打印**页面（左半 QR码+基本信息，右半空白标示卡区）
6. 打印标签，**贴于样品实物上**

### 4.2 补打标签

如标签遗失或打印失败，可到「样品列表」→ 找到对应样品 → 点击「打印」：

- **打印**：弹出标签打印页（含 QR 码 + 编号 + 名称/机型/组别/规格）
- **下载 QR**：下载高分辨率 PNG 二维码，供条码打印软件导入

### 4.3 标签尺寸设置

标签打印页和标示卡打印页顶部提供**尺寸选择器**：

| 尺寸 | 标签 | 标示卡（=标签空白卡区，减 QR 侧边） |
|------|------|--------|
| 小号 | 37×18mm | 20×15mm |
| 中标 | 52×25mm（默认） | 28×20mm |
| 大号 | 60×40mm | 32×35mm |
| 自定义 | 30~150mm 可调 | 减 QR 侧边自动换算（如 60×40 → 32×35mm） |

- 标签打印页：尺寸选择器**可修改**，选择后标签内容按比例缩放
- 标示卡打印页：纸张=标签空白卡区（标签去掉 QR 侧边后的实际贴入区），顶部显示对应尺寸供打印对话框选纸
- 切换尺寸后，已打开页面的布局实时更新

## 五、扫码台（三方共用）

扫码台是系统核心入口，三方通过扫描样品二维码驱动状态流转。进入「扫码台」页面后：

### 5.1 扫码方式

| 方式 | 适用场景 |
|---|---|
| **扫码枪**（推荐） | 桌面端批量作业，对准二维码扫描即可自动填充 |
| **手动输入** | 无扫码枪时，输入 13 位样品编号（如 `G-YD9015-Q-001-01`）或兼容旧编号（`SM-XXXXXX`）后回车。格式不合法将提示错误。 |
| **摄像头扫码** | 手机端（仅 HTTPS 可用），点击「开启摄像头」对准二维码。HTTP 下折叠区会显示不可用提示。 |

**连续扫码**：勾选「连续扫码」后，每次操作完自动清空输入框聚焦，适合扫码枪批量作业。

### 5.2 研发确认制作（RD）

> 流程：新建·待制作确认 → 制作完成

1. 将标签贴于制作完成的样品上
2. 在扫码台扫描该样品二维码
3. 系统显示样品信息，确认无误后：
   - **上传制作照片** *（必填）* — 点击「选择文件」
   - 可选填写**备注**
4. 点击「确认制作完成（研发）」
5. 状态更新为「制作完成」，系统记录操作日志

### 5.3 品保确认发行（QA）

> 流程：制作完成 → 已发行

品保发行使用**分步向导**，分三步完成：

**Step 1 — 设置复检周期**

1. 扫描「制作完成」状态的样品二维码
2. 系统显示样品信息，设置**复检周期（天）** *（必填）* — 默认 **365 天（1 年）**，可手动调整（允许范围 **1~3650 天** 的整数）
3. 实时预览下次复检日期
4. 点击「下一步：填写标示卡」

**Step 2 — 标示卡审查**

1. 全部标示卡字段平铺展开（无折叠），逐字段显示状态标记：
   - `✓ RD已填`（绿色）— 研发已填写
   - `✗ 必填`（红色）— 必填字段未填写
2. 填写必填字段：
   - **样品类型** *（必填）* — OK样品 / NG样品
   - **限度项目** *（必填）* — 26 项下拉选择
3. 可选字段自动带入研发建样时填写的数据：提供处、标准范围、测试数据（有效期自动等于复检日，品保发行/复检时由系统自动填充）。**版次**：发行时自动设为 `01`，复检/再发行时自动 +1（如当前 `01` → 默认填入 `02`，可手动调整，最高 `99`）。
4. 品保确认人自动签署为当前登录用户
5. 点击「下一步：确认发行」（类型+项目未填则无法进入下一步）

**Step 3 — 确认 & 发行**

1. 展示发行摘要：复检周期、下次复检日期、类型、项目
2. 核对无误后点击「确认正式发行（品保）」
3. 系统记录操作日志，自动计算下次复检日期
4. 标示卡自动弹出打印（非连续模式）/ 加入打印队列（连续模式）

### 5.4 品保复检（QA）

> 流程：已发行（已到期）→ 更新复检日期

当样品到了复检日期后，品保需对实物进行复检：

1. 扫描到期样品二维码
2. 系统显示复检操作界面：
   - **上传复检照片** *（必填）*
   - 可选填写**备注**
   - 复检周期默认沿用上次周期，可修改（1~3650 天）
3. **标示卡更新**（选填）— 展开「标示卡更新」折叠区，可修改版次/测试数据，不填则保留原值。有效期自动等于复检日，由系统自动同步。
4. 点击「确认复检完成（品保）」
5. 下次复检日期自动顺延。如填写了标示卡字段，日志会注明「标示卡已更新」
6. **保管中临期复检**（2026-09-01 批次 1 新增）：样品在保管中且距复检日 ≤7 天（含逾期）时，品保扫码可直接执行「到期复检」——样品保持保管中不脱离保管链路，复检通过后顺延复检日、标示卡版次自动 +1 并触发重打。

### 5.5 保管接收（CUSTODY）

> 流程：已发行 → 保管中

1. 收到品保发行的样品后，扫描其二维码
2. 填写**保管储位** *（必填）* — 如「A区-3架-2层」
3. 点击「确认接收保管（XX部）」
4. 状态更新为「保管中」，记录储位和保管部门

### 5.6 保管申请退回（CUSTODY）

> 流程：保管中 → 退回审核中

1. 扫描「保管中」状态的样品二维码
2. 点击「申请退回」按钮
3. 填写**退回原因** *（必填）* — 如「样品外观损坏，需重新制作」
4. 点击「提交退回申请」
5. 状态更新为「退回审核中」，等待品保审核

### 5.7 品保审核退回（QA 4 分支）

> 流程：退回审核中 → 多分支

扫描「退回审核中」状态的样品二维码，系统显示 4 个操作按钮（ADMIN 额外可见兜底操作，见分支 5）：

**分支 1 — 重新发行**

1. 点击「重新发行」
2. 进入品保发行分步向导：设置复检周期 → 修改标示卡信息（版次自动 +1，可手动调整）→ 确认发行
3. 状态更新为「已发行」，按正常流程重新分发

**分支 2 — 退回研发重做**

1. 点击「退回研发重做」
2. 下拉选择指派的研发人员
3. 可选填写作废原因
4. 样品保持「退回审核中」状态，被指派的研发在首页看到待办
5. 研发执行「创建替代品」（见 5.8）后，原样品自动变为「已作废」

**分支 3 — 直接作废**

1. 点击「直接作废」
2. 填写**作废原因** *（必填）*
3. 确认后状态更新为「已作废」

**分支 4 — 拒绝退回**

1. 点击「拒绝退回」
2. 填写**拒绝理由** *（必填）* — 如「样品完好，无需退回」
3. 状态恢复为「保管中」

**分支 5 — ADMIN 兜底（仅管理员，2026-09-01 批次 2 新增）**

退回审核卡死（如 QA 长期未处理、被指派研发离职/停用）时，管理员扫描该样品二维码可直接兜底：

1. **强制改派（FORCE_REASSIGN）**：下拉重新选择**启用状态**的研发人员接管重做（含存在性/角色/启用状态校验），样品保持「退回审核中」，新被指派人首页出现待办
2. **强制作废（FORCE_RETIRE）**：填写**作废原因** *（必填）*，样品直接变为「已作废」，日志以「管理员强制作废：」前缀留痕

### 5.8 研发创建替代品（RD）

> 流程：退回审核中（已被指派）→ 新建替代样品

1. 被指派的研发扫描「退回审核中」样品二维码
2. 点击「创建替代品」
3. 系统自动复制原样品信息（名称、规格、机型、组别、标示卡等）
4. 生成新的样品编号，新样品状态为「新建·待制作确认」
5. 原样品记录被替代关系，新样品按正常流程制作→发行→分发

### 5.9 无权操作

如果扫描的样品状态与当前角色不匹配，系统会提示：

> "你的角色（XXX）无法推进该样品，请确认流程顺序或由对应部门操作。"

常见原因：样品尚未制作完成研发就去确认发行、样品还未发行保管就去接收等。

### 5.10 标示卡打印队列（连续模式）

勾选「连续扫码」时，品保发行后标示卡不清空列表，而是加入打印队列：

1. 每次发行成功，扫码区下方显示 `已积累 N 张标示卡`
2. 全部发行完毕后，点击「打印全部」— 依次弹出标示卡打印页
3. 也可随时「清空」队列
4. 离开页面时如有未打印队列，浏览器会弹出确认提示

> 非连续模式下，发行成功后直接弹出单张标示卡打印页，行为不变。

## 六、样品列表

点击「样品列表」查看所有样品，支持以下筛选：

| 筛选条件 | 说明 |
|---|---|
| 搜索 | 按编号/名称/规格模糊搜索 |

### 6.1 样品详情

## 十三、治具管理（子系统入口）

治具管理系统通过门户进入（`subsystems/fixtures/frontend/index.html`），与样品系统共享用户体系和 CSS 样式，通过左侧菜单切换功能页面。

### 13.1 治具看板

治具看板展示以下四大区块（按优先级排列）：

1. **统计卡片**（7 张）：待验证、可领用、领用中、维修中、改善中、报废。点击卡片筛选下方待办列表，再次点击取消筛选。**待验证 = 制作完成但尚未验证移交的治具**。

2. **逾期未归还预警**：领用超过 30 天仍无归还动作的条目，红色动画标注。

3. **待保养预警**：保养周期内未执行保养的条目，含「上次保养日期」「保养周期」「已逾期天数」。

4. **我的待办**：按当前登录角色自动列出需要你操作的治具（如 ME 看到待验证/待保养，RD 看到待制作/待维修等）。

### 13.2 治具清单

治具清单支持以下筛选和功能：

| 功能 | 说明 |
|---|---|
| 搜索 | 按编号/名称模糊搜索 |
| 状态 | 12 种状态下拉筛选 |
| 部门 | 按申请部门筛选 |
| 排序 | 编号升/降序 |
| 每页条数 | 10/20/50/100 自选 |
| 列宽拖拽 | 拖拽表头右侧把手调整列宽 |
| 响应式 | 移动端自动切换标签-值纵向卡片布局 |

所有状态标签有独立颜色（Green/Blue/Amber/Red/Gray），视觉区分。

清单中**「归还状态」「保养状态」两列**用于一眼区分治具的到期维度：

| 列 | 徽章 | 含义 |
|---|---|---|
| 归还状态 | 正常 / 近7天到期 / 超期N天 / — | 仅领用中（IN_USE）且设了归还期限时判定 |
| 保养状态 | 正常 / 近7天到期 / 逾期N天 / — | 未报废且有保养计划时判定 |

逾期/超期徽章为红色脉冲样式，悬停可查看具体到期日期。与看板「逾期未归还」「待保养」区块判定规则一致。

列表页点击「导出 CSV」可下载当前筛选条件下的全部记录（CSV，Excel/WPS 直接打开）。

### 13.3 新建治具（RD/ADMIN）

1. 点击「新建治具」
2. 填写**治具名称** *（必填）*、**规格**、**型号**、**对应工站**、**分类**（如测试治具/装配治具）、**申请说明**、**保养周期（天）**（选填，默认 90，填 0 表示无需定期保养）
3. 可选：上传设计图纸、采购订单等附件，以及治具照片
4. 点击「提交申请」
5. 系统自动生成编号 `FJ-XXXXXX`（6 位流水号），状态为「已申请」
6. 研发可点击「开始制作」→ 状态变为「已接收」

### 13.4 治具详情弹窗

治具列表/看板中点击详情，弹出详情弹窗（与样品详情弹窗同架构），包含：

- **信息 Tab**：基础信息卡片（编号/名称/规格/数量/机型/申请部门）、文件分组（设计图纸/采购订单/治具照片/保养照片/现场照片）、操作日志（最近 2 条，可点击「查看全部 N 条」）
- **全量日志 Tab**：当前治具的全部操作记录表格（时间/动作/角色部门/备注）
- 底部操作按钮按当前状态和角色动态显示（制作/验证/移交/领用/报修/维修/确认/报废/取消等）

### 13.5 治具扫码台

治具扫码台类似样品扫码台，通过扫描治具二维码驱动状态流转：

| 操作 | 触发状态变化 | 执行角色 |
|---|---|---|
| **确认制作** | REQUESTED/ACCEPTED → VERIFY_PENDING | RD |
| **验证移交** | VERIFY_PENDING → TRANSFERRED | 申请部门人员（谁申请谁验证，ADMIN 兜底） |
| **领用** | TRANSFERRED → IN_USE | ME/QA/CUSTODY（治具管理方） |
| **归还** | IN_USE → TRANSFERRED | 领用人 |
| **ME 报修** | IN_USE → REPAIRING_ME | ME |
| **退回 RD 维修** | IN_USE → REPAIRING_RD | ME |
| **RD 维修完成** | REPAIRING_RD → REPAIR_DONE | RD |
| **ME 维修确认** | REPAIRING_ME/REPAIR_DONE → TRANSFERRED | ME |
| **申请改善** | IN_USE → IMPROVING | ME |
| **改善完成报废** | IMPROVING → RETIRED | ADMIN |
| **直接报废** | TRANSFERRED → RETIRED | ADMIN |
| **取消治具** | 仅已申请/已接收状态 | RD/ADMIN |

**验证规则（单人验证，2026-09-04 收紧）**：
1. 制作完成后，由**申请部门人员**扫码验证即可移交（「谁申请谁验证」+ ADMIN 兜底），无需研发二次确认
2. RD 不参与验证（避免制作方自证）；`VERIFY_RD_OK/VERIFY_ORG_OK` 为旧双人验证的历史状态，存量数据兼容，仅 ADMIN 可强制移交解锁

**我的待办口径（行动主体才看待办）**：治具待办只投递当事人与职能口，不做部门广播——
- 待接收/制作中/RD维修中 → 仅 RD；ME维修中/待确认维修/保养到期 → 仅 ME
- 待验证/可领用/改善中 → 申请部门（+ RD/ME 按分工）
- 归还逾期 → 借用人本人 + 借用部门 + ME（其他部门保管不再广播）

### 13.6 治具保养体系

- 治具移交时设置**保养周期**（天）
- 看板**待保养预警**自动检测逾期保养
- 保养时上传保养照片、填写备注
- 保养记录全量留痕

### 13.7 治具文件管理

- 支持上传 6 类文件：设计图纸(pdf/dwg/dxf/stp)、采购订单(pdf/doc/xls)、治具照片(jpg/png)、保养照片、现场照片、其他(pdf/doc/zip)
- 每类文件有 MIME 白名单校验
- 图片类 ≤10MB，其他 ≤20MB
- 文件按类型分组展示

### 16.3 任务详情（v2：主卡 + Tabs 分区）

  - **关联**：关联样品 / 治具 / 关联任务（下拉选择，并管理既有关联）
  - **日志**：任务全量操作留痕

> 编辑任务时，**前置依赖**（其他任务）与**关联样品/治具**均使用下拉选择器，无需手填编号；依赖关系带环检测与阻塞校验，非法依赖会提示无法保存。

### 16.4 项目管理

- 项目列表页：新建项目、编辑、成员管理（添加成员 / 转让 owner / 移除成员）
- 已有任务的项目禁止删除（提示 409）；状态机管理（仅 ADMIN）：编辑「未开始/进行中/已完成/已延期」四态标签与颜色、转移规则

## 十七、管制流程子系统

不良品管制全流程数字化（入口：门户 →「管制流程管理」），电子表单对应纸质 **GYS-Q2-008_01《不良品委托检验单》**，全程留痕、会签闸口把关、数量闭环。

### 17.1 全流程一览

```
新建申请(DRAFT) → 提交会签 → 管制会签中(SIGNING) → 闸口①通过/贴标 → 已贴标签(LABELED)
  → 入管制仓 → 已入管制仓(CONTROL_STORED) → 开不良品委托单 → 委托单已开(NCR_DONE)
  → 发起处理方式会签 → 处理会签中(DISPOSAL_SIGNING) → 闸口②通过 → 重工工单已开(REWORK_OPENED)
  → 生产确认开工 → 重工执行中(REWORKING) → 报工确认 → 已报工 → 入库 → 已入库 → 出货 → 已出货
（任意中间态 ADMIN 可作废；退回唯一入口 = 会签弹窗选「退回」：闸口①任一字位退回 → 回申请草稿，闸口②退回 → 回委托单已开；重新提交后该闸口全部字位重新会签）
```

### 17.2 新建管制申请（各部门）

1. 左侧菜单「新建管制申请」
2. 填写：**料号** *（必填）*、**品名** *（必填）*、销货单号、机型、**数量** *（必填，>0）*、**不良类型** *（必选：外观/功能/尺寸/性能/包装/其它）*、**管制/不良原因** *（必填）*、喷码日期、客户等
3. 提交后自动生成管制单号 `CTL-YYYYMMXXX`，状态「申请草稿」，并初始化闸口①会签模板（品保→研发→生管→制造部→仓库 5 个字位）
4. 草稿可编辑（仅申请人或 ADMIN）、可由 ADMIN 作废

### 17.3 提交会签（起草人所在部门）

- 谁申请谁提交：DRAFT 单的「提交会签」待办/按钮只出现在**申请部门**（QA/CUSTODY/ME 三类角色可执行该动作，ADMIN 兜底）
- 点击后确认，状态 → 管制会签中

### 17.4 会签（并行 + 按部门区分）

- **并行会签**：闸口① 5 个字位（品保/研发/生管/制造部/仓库）不分先后，可同时签；闸口② 2 个字位（品保/研发）
- **按部门区分（2026-09-04）**：每人只能签**自己部门**的字位——制造部保管签「制造部」步，不能替生管/仓库签；部门别名自动对应（品保=品保文管中心、研发=研发部/测试部、生管=生管部、仓库=资材部）
- **入口统一**：详情主卡「操作」区最左的「去会签（闸口①/②）」按钮（只有轮到你的字位才出现）；「会签闸口」页签只看各字位签核状态
- 签字时选 **同意 / 退回** 并填意见；任一字位退回 → 整单回退（闸口①退回申请草稿，闸口②退回委托单已开），退回人意见必填
- **退回是会签动作不是流转按钮**（2026-09-04 会签退回闭环）：操作区没有独立的「会签退回」按钮；退回唯一入口就是上面的「去会签」弹窗选「退回」（意见必填、留痕到会签记录）
- **退回后重新提交 = 全新一轮会签**：起草人修改后点「提交会签」（或 QA 重新「发起处理方式会签」），系统**清空该闸口全部旧签字**（上轮的同意/退回记录作废，结论以操作日志留痕为准），所有字位重新签——不会出现旧签字带病生效
- ADMIN 可代签任意字位、可强制跳过（SKIP）

### 17.5 贴标与入仓

| 动作 | 执行者 | 说明 |
|---|---|---|
| 闸口①通过/贴标 | QA | 全部 5 字位同意后执行；自动生成管制标签号 LB-单号；「管制标签打印」页打印标签 |
| 入管制仓 | 仓库口（资材部 CUSTODY）| 弹窗填**管制仓储位**（必填） |

### 17.6 不良品委托检验单（NCR 无纸化）

1. **开不良品委托单**（QA，已入管制仓状态）：弹窗自动预填**委托单号** `NCR-<管制单号>-<两位序号>`（同一管制单可开多张，序号自动递增，可手改），选择**检验部门**与**处理部门**后提交
2. **电子表单**：详情页「电子表单」Tab 按 GYS-Q2-008_01 栏位渲染单张可打印表单，点击「打印」直接出单。表单头部显示委托单号；各分区内容：
   - 基本信息（销货单号/料号/品名/机种/客户/喷码日期/数量/不良类型）
   - 不良原因分析（管制原因 + 外观/功能/尺寸/设变/其他）
   - 解决方案（处理方式结论、包装SOP编号）
   - 重工/全检标准（重工SOP、现场指导、其他标准文件）
   - 处理结果（全检/重工数量=良+不良+报废、合格品/不良品/报废数、报废原因、批次号、包装称重、确认人、数量一致）——数量为**全部报工批次累计值**，与出货结余校验同源
   - 签署栏（检验部门/处理部门/委托部门/经办）
3. **追加委托单**：同一管制单需要多次检验时，在 NCR_DONE 之后仍可从详情追加（单号序号自动递增）

### 17.7 处理方式会签与重工执行

| 动作 | 执行者 | 录入内容 |
|---|---|---|
| 发起处理方式会签 | QA | **重工SOP**（必填）+ 现场指导/其他标准文件（至少一项）+ 包装SOP（选填）；提交后初始化闸口②模板（品保+研发） |
| 闸口②通过 | QA+RD 各自字位 | 弹窗填**处理方式结论**（自动写入电子表单） |
| 生产确认开工 | ME | 弹窗填**重工工单号** |
| **追加报工** | 生产口 CUSTODY（制造/生管/资材部）/ ME | **重工结果在这里录入**：良品数、不良数、报废数、报废原因、批次号、包装称重、确认人、数量一致；可**多次分批报工**，每次主单数量自动累加、结余自动重算 |
| 报工（确认） | 同上 | 确认流转「已报工」；系统校验：**必须已有报工记录且结余清零**（余数≠0 会拦截提示继续报工） |
| 入库 | 仓库口 CUSTODY / ME | 纯确认，系统记入库时间 |
| 出货 | 仓库口 CUSTODY / ME | 纯确认；出货前复核**结余必须=0**（数量=良+不良+报废），否则拦截 |

### 17.8 详情页结构与操作区

- **主卡**：单号+状态徽章、字段分组卡（基本信息/管制信息/执行结果/备注）、11 步流程进度条、5 阶段卡（申请与会签/贴标与入仓/NCR与处理会签/重工执行/入库出货）
- **操作区（统一按钮区）**：`去会签（闸口①/②）` → `追加报工` → 流转按钮 → `作废（仅 ADMIN）`——轮到你的动作才显示（退回不在此区，见 17.4 会签弹窗）
- **明细 Tabs**：会签闸口（签核状态）/ 不良品委托单（历次 NCR）/ 报工（历次报工记录表）/ 操作日志 / 电子表单
- 待办提示：看板「待我签核」在轮到你签时显示「待我会签」，优先于退回类提示

### 17.9 管制看板与列表

- **管制看板**：状态分布统计 + 待办区（待我流转/待我签核两栏）
- **我的待办页**：当前角色全部待办，单击直达详情
- **管制单列表**：状态/申请部门/不良类型/关键词筛选，超期单（默认 48h 无动作，ADMIN 可在设置中调阈值）高亮；「已贴标」快捷筛选用可打印清单
- **不良品委托单页**：跨单据的 NCR 清单（单号/状态/日期筛选 + CSV 导出）
- **操作日志**：全系统管制操作留痕（仅 ADMIN）

## 十八、全局工作台 · 我的待办

跨子系统聚合「轮到我处理」的事项（入口：门户 →「全局工作台」→ 左侧「我的待办」），按子系统分组展示，每条可单击直达详情处理。

### 18.1 口径：行动主体才看待办

待办 ≠ 权限广播——只有**当事人/职能口**会收到待办，旁观部门不被打扰：

| 分组 | 待办规则（谁看到什么） |
|---|---|
| 样品 | RD=待制作确认/退回重做指派；QA=待发行/退回审核；保管/生技=待接收（保管部门共享池）；ADMIN=以上并集 |
| 治具 | RD=待接收/制作中/RD维修/改善中；ME=ME维修/待确认维修/保养到期/改善中；申请部门=待验证/可领用/改善中；归还逾期=借用人本人+借用部门+ME；死锁态=ADMIN |
| 管制 | 待我流转（按状态+角色，DRAFT 仅申请部门，仓口动作仅对应部门）+ 待我签核（轮到自己部门字位的会签）；ADMIN 见全部会签中单据 |
| 项目 | 指派给我的未完成任务/子任务（含延期标记） |

- 紧急项（归还逾期、保养到期、死锁）带**紧急**标记置顶提示
- 每条显示：编号、名称、待办动作、当前状态；项目任务显示完成期限
- 数据实时派生不落库，处理完刷新即消失

### 18.2 与各子系统待办的分工

各子系统内部也有自己的待办入口（管制看板待办区/样品看板我的待办等）；工作台「我的待办」是**五系统合一的总入口**，适合每天开工先扫一遍。数字口径与各子系统互相印证（同源派生）。
