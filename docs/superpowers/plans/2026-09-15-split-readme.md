## 3. 拆分方案

**方案 A（推荐）**：`## API 一览`（4,457 字符）外迁 `docs/api.md`，README 原位留 3~5 行指针。
- 依据：AGENTS.md §13 已把 `docs/api.md` 列为接口文档的规范位置，非新造载体。
- 效果：19,714 − ≈4,340 = **≈15,374 字符（76.9%）**，一步脱离 90% 告警区。

**方案 B（方案 A 之后按需）**：再把 `## 目录`（2,032 字符）外迁或精简为顶层骨架 → 约 13,400 字符（67.0%）。

**顺带清理（低风险）**：`### 演示账号`（L224，projects 子系统的 `pm01`）与 `## 演示账号`（L302，全局 8 账号表）**标题同名易混淆**，前者改名为 `### 项目追踪演示账号` 并与后者互链。

## 4. 实施步骤

1. 新建 `docs/api.md`，把 README **L315-383** 的 5 张 API 表整体迁入（保持表头、列序、行序不变）。
2. README 原位置保留 `## API 一览` 标题 + 指针行，例如：
   `> 完整接口清单（5 个子系统，含鉴权/角色口径）见 [`docs/api.md`](./docs/api.md)`
3. 重名小节改名并互链（见第 3 节末）。
4. **校验受保护标记块未被动过**：README L7/L13 的 `<!-- AUTO-SUBSYSTEMS:START/END -->` 由 `tools/sync-subsystem-docs.js` 生成，**禁止手改**；迁移范围严格限定在 L315-383，不与其相交。
5. 检索并同步引用 README 锚点的其它文档（`grep 'README.md#' docs/ *.md`）。
6. 更新 AGENTS §14 / CLAUDE §6 的 README 容量条目 —— **本项需用户明确授权**（规则文件禁擅自改）。
7. 运行 `node tools/sync-subsystem-docs.js`，确认 `git diff` 中标记块内容无变化。
